Throughout the three missions, I learned that generating a response with a foundation model does not guarantee accurate or reliable robot behavior. The quality of the instructions, available sensory information, and validation of actions all influence the results.

In Mission 1, the language model initially made unsupported assumptions about the robot's starting position and the cup's condition. My revised request explicitly described the task and physical limitations, resulting in a more accurate and feasible plan. However, the response only proposed actions and did not actually execute them. In Mission 2, the vision language model incorrectly identified a drawing compass as a tape measure. Even after I improved the request by describing visible features, the model called it pliers. This demonstrated that more detailed prompting can produce more explanation without improving visual accuracy. In Mission 3, none of the navigation prompts successfully reached the target. My improved prompt provided explicit waypoints, but the robot still stopped 23 times and attempted 21 blocked moves, ending at (1,1). Although the simulator prevented movement through walls, it could not make the model follow the correct route.

Overall, these experiments showed that robot systems need clear instructions, reliable perception, and action validation. A remaining limitation is the model's inability to consistently use its current state to select appropriate actions, even when provided with a valid navigation plan.
